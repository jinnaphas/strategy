# ทะเบียนกลยุทธ์ (Strategy Register)

ทะเบียนกลยุทธ์คือ "แหล่งความจริงเดียว" (single source of truth) ของกลยุทธ์ในรูปแบบที่ **ทั้งคนและ AI Agents อ่านได้** ใช้เป็นฐานของ Strategy Radar และ Agent อื่น ๆ ในอนาคต

> 🔒 ไฟล์จริง `strategy-register.yaml` ถูก `.gitignore` ไว้ เพราะ repo นี้เป็น public — ดูตัวอย่างที่ `strategy-register.example.yaml`

## โครงสร้างข้อมูล

| ฟิลด์ | ความหมาย | ใช้ทำอะไรใน Radar |
|---|---|---|
| `id` | รหัสกลยุทธ์ เช่น `P1-S1` | อ้างอิงในรายงานและ signal log |
| `name`, `pillar`, `level`, `owner` | ชื่อ เสาหลัก ระดับ (corporate/business/functional) เจ้าของ | เสนอผู้รับผิดชอบ |
| `objective`, `targets[]` | วัตถุประสงค์และ KPI/เป้าหมาย | ประเมินว่าข่าวกระทบ KPI ใด |
| `where_to_play` | ลูกค้า ตลาด พื้นที่ | จับคู่ข่าวลูกค้าและตลาด (D1, D2) |
| `how_to_win` | วิธีชนะ | ประเมินว่าข่าวทำให้ความได้เปรียบเปลี่ยนหรือไม่ (D3, D4) |
| `key_technologies` | เทคโนโลยีหลัก | จับคู่ข่าวเทคโนโลยี (D4) |
| `stakeholders` | ลูกค้า คู่แข่ง พันธมิตร ผู้กำกับดูแล | จับคู่ข่าว Industry/Policy (D3, D5, D9) |
| `assumptions[]` | **สมมติฐานที่กลยุทธ์พึ่งพา** + `signposts` (สัญญาณที่บอกว่าสมมติฐานเริ่มไม่จริง) | Assumption Watch — ส่วนที่มีค่าที่สุดของ Radar |
| `watch.keywords_th/en`, `watch.queries` | คำค้นสำหรับเฝ้าระวัง | สร้าง query plan |

## หลักการเขียนทะเบียนที่ดี

1. **หนึ่งกลยุทธ์ = หนึ่งทางเลือกที่ชัด** ไม่ใช่รายการกิจกรรม
2. **เขียนสมมติฐานให้ทดสอบได้** เช่น "ภาครัฐเปิดประมูล Smart Meter ต่อเนื่องปีละไม่น้อยกว่า X" ดีกว่า "ตลาดเติบโต"
3. **Keyword ใช้คำที่สื่อใช้จริง** ทั้งไทยและอังกฤษ และห้ามใส่ข้อมูลลับใน `watch` (คำเหล่านี้จะถูกส่งไปยังเครื่องมือค้นหา)
4. **ทบทวนทุกไตรมาส** พร้อม Strategy Review Meeting — รับข้อเสนอ keyword/สมมติฐานใหม่จากส่วน Blind Spots ของรายงาน radar
