# อ่านง่าย: ชื่อแทนรหัส และเส้นทางเหตุผล 5 ขั้น

> ต่อจาก [06 — Market & Customer Intelligence และ 7QC Tools](06-market-customer-intelligence-and-qc-alerts.md)
> เอกสารนี้เป็นแบบโครงสร้าง (design) ทั่วไป ไม่มีข้อมูลกลยุทธ์จริงขององค์กร

## 1. ปัญหา: รหัสเยอะจนคนอ่านไม่ออก

ระบบมี Agent หลายตัว แต่ละตัวสร้างรหัสของตัวเอง เมื่อนับรวมมีราวสิบห้าตระกูล

| ตระกูลรหัส | ตัวอย่าง | ใช้ทำอะไร |
|---|---|---|
| กลยุทธ์ · สมมติฐาน | `P1-S1` · `P1-S1/A2` | เชื่อมสัญญาณกับทะเบียนกลยุทธ์ |
| Must-Win · ประเด็นข้อมูล · วันสำคัญ | `B1` · `I01` · `E01` | เชื่อมงาน ข้อมูลที่ค้าง และวันประชุม |
| สัญญาณ · ประมูล · พันธมิตร | `SIG-…` · `TND-…` · `PTN-…` | หลักฐานจากภายนอก |
| Solution · เสียงลูกค้า · ตัวเลข | `EMG-…` · `VOC-…` · `MKT-` `IND-` `INT-` | ทางเลือก เสียงลูกค้า และ series ตัวเลข |
| Agent | `A0`–`A9`, `A1H` | ผู้สร้างข้อมูล |
| มาตรวัด | `D1`–`D10` · `H0`–`H3` · `R1`–`R4` | ด้านที่กระทบ · ระยะเวลา · กฎเตือนตัวเลข |

รหัสจำเป็นสำหรับระบบ เพราะทำให้ข้อมูลเชื่อมกันได้แม่นยำ แต่เมื่อ Agent เขียนรหัสลงในประโยค และหน้าจอแสดงรหัสแทนชื่อ ผู้บริหารต้องจำรหัสก่อนจึงจะเข้าใจ เช่น

> ~~"P1-S1 disrupted และ B3 ยัง proposed 0/3 action (A6 เสนอ off_track)"~~

## 2. หลัก: รหัสให้ระบบจำ ชื่อให้คนอ่าน

| ชั้น | ทำอะไร |
|---|---|
| **ข้อมูล** | เก็บรหัสในช่องที่เป็นรหัส (`strategies`, `battles`, `refs`, `drivers` …) ตามเดิม เพื่อให้เชื่อมโยงกันได้ |
| **Agent (ต้นทาง)** | ข้อความทุกช่องที่คนอ่านใช้ **ชื่อสั้น** ไม่ใช้รหัส ไม่ใช้คำสถานะภาษาอังกฤษ — กำหนดเป็น "Writing style for people" ในคำสั่งของทุก Agent |
| **หน้าจอ (ปลายทาง)** | แปลงรหัสที่ยังหลงเหลือเป็นชื่ออัตโนมัติ กดชื่อเพื่อเปิดต้นทาง ชี้ค้างเพื่อดูรหัส · ครอบคลุมรายงานเก่าด้วย |

ประโยคเดิมจะอ่านได้แบบนี้

> "กลยุทธ์ **ธุรกิจหลัก → รายได้ประจำ** ถูก Disrupt และ Must-Win **รักษาลูกค้าฐานเดิม** ยังรออนุมัติ (งานเสร็จ 0 จาก 3) — ผู้ติดตามแผนประเมินว่าหลุดแผน"

## 3. ตารางแปลงรหัสเป็นคำ

| รหัส | แสดงเป็น |
|---|---|
| กลยุทธ์ / Must-Win | ชื่อสั้นจากทะเบียน (`short`) |
| สมมติฐาน `…/A2` | "สมมติฐานข้อ 2" + ข้อความสมมติฐานเมื่อชี้ |
| สัญญาณ | "ข่าว: …" · "คู่แข่ง: …" · "Ecosystem: …" · "ระยะยาว: …" · "ลูกค้า: …" ตามผู้สร้าง ตามด้วยหัวข่าว |
| ประมูล · พันธมิตร · Solution · เสียงลูกค้า · ตัวเลข | "ประมูล: ชื่องาน" · "พันธมิตร: ชื่อบริษัท" · "Solution: ชื่อทางเลือก" · "เสียงลูกค้า: ธีม" · "ตัวเลข: ชื่อ series" |
| ประเด็นข้อมูล · วันสำคัญ | "ประเด็นข้อมูล: หัวข้อ" · "วันสำคัญ: ชื่อ (วันที่)" |
| `D1`–`D10` | ตลาด · ลูกค้า · แข่งขัน · เทคโนโลยี · นโยบาย · ต้นทุน · การเงิน · คน · Ecosystem · ESG |
| `H0`–`H3` | ภายใน 3 เดือน · ภายใน 1 ปี · 1–3 ปี · มากกว่า 3 ปี (ช่วง เช่น H2–H3 = "1 ปีขึ้นไป") |
| `R1`–`R4` | หลุดกรอบควบคุม · เกือบหลุดกรอบ · ระดับเปลี่ยน · ขยับทางเดียวต่อเนื่อง |
| คำสถานะ | `disrupted` ถูก Disrupt · `at_risk` มีความเสี่ยง · `on_track` ตามแผน · `off_track` หลุดแผน · `proposed` รออนุมัติ · `weakening` เริ่มสั่นคลอน · `challenged` ถูกท้าทาย |
| แหล่งข่าว Tier A–D | แหล่งทางการ · สื่อหลัก · สื่ออุตสาหกรรม / ที่ปรึกษา · ยังต้องตรวจสอบ |

### ชื่อเรียกทีม AI

| รหัส | ชื่อเรียก | งาน |
|---|---|---|
| A0 | ผู้สรุปภาพรวม | สรุปผู้บริหาร 1 หน้า |
| A1 | เรดาร์ข่าวรายวัน | ข่าวและข้อมูลภายนอกทุกเช้า |
| A1H | มองไกล 1–5 ปี | สัญญาณอ่อนและตัวชี้วัดภายนอก |
| A2 | ประมูลและคู่แข่ง | ประกาศจัดซื้อ ผลผู้ชนะ คู่แข่ง |
| A3 | ผู้ออกแบบทางเลือก | Solution พร้อมทางเลือกให้ตัดสินใจ |
| A4 | จัดสรรงบลงทุน | (วางแผน) |
| A5 | หาพันธมิตร | พันธมิตรและ Ecosystem |
| A6 | ผู้ติดตามแผน | งาน Must-Win ประเด็นข้อมูล สัญญาณค้าง |
| A7 | ผู้ประเมินแผน | สถานะทุกกลยุทธ์และสมมติฐาน |
| A8 | ผู้ร่างเอกสารประชุม | สไลด์ EC / BOD |
| A9 | เสียงลูกค้าและตลาด | ตัวเลขอุปสงค์ เสียงลูกค้า แพ้–ชนะ |

ชื่อเรียกเลือกจาก **งานที่ทำ** ให้คนนอกทีมกลยุทธ์เข้าใจทันที ปรับได้ตามที่องค์กรคุ้นเคย

## 4. เส้นทางเหตุผล 5 ขั้น

ทุกเรื่องที่ Disrupt แผนแสดงเป็นลูกโซ่ซ้ายไปขวา (บนมือถือเป็นบนลงล่าง) แทนการกองรหัสหลักฐานไว้รวมกัน

```mermaid
flowchart LR
    E["1 เกิดอะไร<br/>ข่าว · ตัวเลข · เสียงลูกค้า"] --> S["2 กระทบกลยุทธ์ไหน<br/>ชื่อ + ไฟสถานะ + คำสถานะ"]
    S --> A["3 สมมติฐานไหนสั่น<br/>ข้อความสมมติฐาน"]
    A --> M["4 Must-Win ไหนโดน<br/>ชื่อ Must-Win"]
    M --> D["5 ต้องทำอะไร<br/>ข้อเสนอ · เจ้าของ · กำหนด"]
```

| ขั้น | ดึงจาก |
|---|---|
| 1 เกิดอะไร | `refs` ของเรื่องนั้น (สัญญาณ ประมูล พันธมิตร เสียงลูกค้า ตัวเลข ประเด็นข้อมูล วันสำคัญ Solution) |
| 2 กระทบกลยุทธ์ | `strategies` + สถานะแผนจากผู้ประเมินแผนสัปดาห์นั้น |
| 3 สมมติฐานที่สั่น | สมมติฐานของกลยุทธ์ข้างบนที่สถานะ "เริ่มสั่นคลอน" หรือ "ถูกท้าทาย" |
| 4 Must-Win ที่โดน | `battles` ของเรื่อง หรือ Must-Win ที่ผูกกับกลยุทธ์เหล่านั้น |
| 5 ต้องทำอะไร | `proposal` · `owner` · `by` |

การ์ดสัญญาณแต่ละใบใช้ลูกโซ่ 4 ขั้นแบบเดียวกัน: เกิดอะไร → กระทบกลยุทธ์ / ด้าน → สมมติฐานที่เกี่ยว → ควรทำอะไร

## 5. สองโหมดการแสดงผล

| โหมด | รหัส |
|---|---|
| ผู้บริหาร | ไม่แสดงรหัสเลย |
| ทีมกลยุทธ์ | ปิดไว้เป็นค่าเริ่มต้น · กด "แสดงรหัส" เพื่อเห็นรหัสตัวเล็กข้างชื่อเมื่อต้องอ้างอิงกับทีม |

หน้า **คู่มืออ่านระบบ** ใน Cockpit รวม: 3 คำถามที่ระบบตอบ · เส้นทางเหตุผลพร้อมตัวอย่างจริง · ทีม AI และหน้าที่ดูผล · คำที่ใช้บอกสถานะ · ตารางรหัสสำหรับอ้างอิง (พับไว้) · พิมพ์ได้

## 6. ตรวจว่าได้ผล

นับรหัสดิบที่มองเห็นบนทุกหน้าของ Cockpit (ด้วยสคริปต์ที่เปิดทุกหน้าแล้วนับรูปแบบรหัส) ก่อนและหลังปรับ — เป้าหมายคือเหลือเฉพาะในตารางอ้างอิงที่ตั้งใจแสดง และตรวจรายงานของ Agent รอบถัดไปว่าข้อความไม่มีรหัสปน
