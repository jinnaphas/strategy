# กติกาการติดป้ายธุรกิจ (Business Line Tagging)

ใช้กับทุก Agent ที่สร้างเรื่องใหม่ลง Strategy Cockpit: ข่าว/สัญญาณ (`signals`) ประมูล (`tenders`) พันธมิตร (`partners`) ทางเลือกเชิงกลยุทธ์ (`emerging`) และเสียงลูกค้า (`voice`)
เป้าหมาย: ให้ผู้บริหารเห็นข่าวแยกตามบริษัทหรือสายธุรกิจในเครือ ตั้งแต่วันที่ข่าวเข้าระบบ

## แหล่งข้อมูล

ตารางสายธุรกิจอยู่ในฐานข้อมูล Cockpit ที่ `meta/business` ทีมกลยุทธ์แก้ตารางนี้ได้เองในหน้า "การจัดกลุ่มธุรกิจ" ของ Cockpit โดยไม่ต้องแก้โค้ด

```text
meta/business
  lines[]   key · order · name · short · co (ชื่อบริษัทที่แสดง) · companies[] · desc · strategies[] · fallback
  aliases[] from · to · since · note      (บริษัทที่เปลี่ยนชื่อ)
```

อย่าเขียนรายชื่อสายธุรกิจหรือรหัสบริษัทลงในไฟล์ของ repo นี้ ให้อ่านจาก `meta/business` ทุกครั้ง

## กติกา

1. ตั้งต้นด้วยทุกสายธุรกิจที่มีกลยุทธ์ตรงกับ `strategies` ของเรื่องนั้น (หนึ่งเรื่องอยู่ได้หลายสายธุรกิจ)
2. เพิ่มสายธุรกิจอื่นได้เฉพาะเมื่อเนื้อข่าวพูดถึงสินค้า ลูกค้า หรือบริษัทของสายนั้นโดยตรง แล้วเขียนเหตุผลสั้น ๆ หนึ่งประโยคใน `businessWhy` ถ้าไม่ได้เพิ่มให้ `businessWhy = ""`
3. ถ้าไม่ตรงสายใดเลย ให้ใช้สายที่ `fallback: true` (ภาพรวมทั้งกลุ่ม)
4. ใช้เฉพาะ `key` ที่มีใน `meta/business.lines` เรียงตาม `order` ห้ามสร้าง key ใหม่ ถ้าไม่มี `meta/business` ให้เขียน `business: []` และแจ้งใน limitations
5. ชื่อบริษัทในข้อความ (owner, nowhat ฯลฯ) ใช้ชื่อใหม่ตาม `aliases` เสมอ
6. ห้ามแก้ `business`, `businessBy` หรือ `businessWhy` ของเรื่องที่มีอยู่แล้ว เพราะทีมอาจปรับไว้ (ทีมแก้รายข่าวแล้วระบบบันทึก `businessBy: "team"`)

## ฟิลด์ที่เพิ่มในแต่ละเรื่อง

| ฟิลด์ | ค่า | ใครเขียน |
|---|---|---|
| `business` | รายการ key ของสายธุรกิจ | Agent ตอนสร้าง · ทีมแก้ได้ |
| `businessWhy` | เหตุผลเมื่อเพิ่มสายนอกตาราง หรือ `""` | Agent |
| `businessBy` | `"team"` เมื่อทีมปรับ | Cockpit |
| `businessAt` | วันที่ทีมปรับ | Cockpit |

## Cockpit แสดงผลอย่างไร

ป้ายที่ทีมปรับมาก่อน ถัดมาคือป้ายที่ Agent ระบุ ถ้าเรื่องใดยังไม่มีป้าย Cockpit จะจัดตามตารางล่าสุดทันที
เรื่องที่ติดป้ายแล้วจะไม่ย้ายตามตารางที่แก้ภายหลัง
